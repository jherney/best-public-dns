Method, DNSSEC probe, and limitations

The app builds DNS queries and submits them to resolver DNS-over-HTTPS endpoints using the GET form of DoH. Well-known domains approximate cached lookup performance; random subdomains under example.com encourage a recursive lookup. Timings are browser fetch measurements, not ordinary UDP or TCP DNS latency, and CORS or network controls can make a resolver appear to fail.

DNSSEC validation is probed by querying dnssec-failed.org, a domain deliberately mis-signed so that validating resolvers answer SERVFAIL while non-validating resolvers return a record. Resolvers marked "validating" pass this probe; a failure to probe is reported as unknown rather than assumed.

Privacy, security, family, and ad-blocking scores are editable heuristics in the source file, based on each provider's public documentation. They are not measurements, endorsements, or legal assessments. Filtering behaviour also varies by query name and over time.
